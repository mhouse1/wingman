## Priority 1 — Correctness / Will crash or misbehave

### 1.1 `GAME_END_B` has no timeout guard — system can stall at end-of-match forever

**File:** [wingman/main.py](../../wingman/main.py) — lines 223–230; [wingman/analyzer.py](../../wingman/analyzer.py) — `_game_end_b` flag
**Issue:** When click-to OCR detects "Click to Continue", `_game_end_b` is set to `True` and stays `True` until one of three things clears it:
- `_set_last_mission()` — only called when a new mission starts
- Respawn or incoming OCR detection — only possible in GAME_BATTLE
- `_game_lobby = True` being set — only set by `click_grid_region()` on the ready_button

If the click-to OCR cache gets stuck returning `True` (e.g., the background thread stalls or the region never clears), the system stays in `GAME_END_B` indefinitely. The main loop keeps calling `click_grid_region(click_to_region)` every cycle, but never transitions to `GAME_LOBBY`. The unattended cycle stalls permanently — no new mission is ever started.

No fallback timer exists at the game-state level (compare: respawn recovery has a 20s fallback timer).

**Fix:** Add a `_game_end_b_since` timestamp. In `analyze_frame()` or in the main loop, if `GAME_END_B` has been active for longer than a threshold (e.g., 30s) without a state transition, clear `_game_end_b` and log a warning to allow recovery:
```python
# In main.py, after detecting GAME_END_B entry:
game_end_b_since = time.time()

# In the main loop:
if current_game_state == GameState.GAME_END_B:
    if time.time() - game_end_b_since > 30.0:
        logger.warning("GAME_END_B timeout — forcing recovery to GAME_BATTLE")
        analyzer._game_end_b = False
        game_end_b_since = 0.0
```

## Priority 2 — Robustness / Will silently fail or degrade

### 2.1 Maneuver cancel hotkey fires on key bleed from GAME_STARTING → GAME_BATTLE

**File:** [wingman/controller.py](../../wingman/controller.py) — `maneuver_cancel_hotkey` lines 93–108; constants lines 21–24
**Issue:** `ROLL_LEFT_KEY = 'j'` is registered as a maneuver cancel hotkey that fires in `GAME_BATTLE`. The game_starting loop does not press 'j' (it presses `MISSION_J20_KEY = 'u'`), but 'j' is a game UI key. Observed in session logs (2026-03-24 04:35:33): 324ms after the state transitioned to `GAME_BATTLE` and `mission_j20` acquired the lock, a 'j' keydown event arrived and immediately cancelled the mission.

Root cause: the keyboard library's global listener captures all key events including those delivered by the OS or game input buffer at the moment of screen transition. There is no grace period between `GAME_STARTING → GAME_BATTLE` and when the maneuver cancel hotkey becomes active.

**Fix:** Track the timestamp of the last game state transition to `GAME_BATTLE`. In `maneuver_cancel_hotkey`, ignore events that arrive within 2 seconds of that transition:
```python
def maneuver_cancel_hotkey(e):
    if self._game_battle_since and time.time() - self._game_battle_since < 2.0:
        logger.debug("Maneuver key '%s' ignored — within 2s grace period of GAME_BATTLE entry", ...)
        return
    ...
```
`_game_battle_since` is set in `_set_last_mission()` (which marks the GAME_BATTLE entry point).

## Priority 3 — Observability / Hard to debug in production

### 3.1 No production instrumentation — OCR latency and event counts are invisible

**File:** [wingman/analyzer.py](../../wingman/analyzer.py) — `_run_ocr_in_background()` lines 723–820; [wingman/main.py](../../wingman/main.py) — main loop
**Issue:** OCR cycle times are logged at DEBUG level per cycle (e.g., `Parallel OCR Timings - Extract: 0.00s | Respawn: 1.23s | Total: 1.24s`) but there is no aggregation, no histogram, and no summary output. Diagnosing a performance regression requires grepping raw logs and manual analysis.

There are no counters for:
- Total OCR cycles run
- Respawn detections triggered
- Incoming detections triggered
- Mission restarts attempted / succeeded
- Click-to detections triggered

This makes it hard to answer "is the system behaving normally?" during a long session without reading hundreds of log lines.

**Fix:** Add lightweight in-memory counters to `GameStateAnalyzer` and emit a summary log every N minutes or on `cleanup()`:
```python
self._stats = {
    'ocr_cycles': 0,
    'respawn_detections': 0,
    'incoming_detections': 0,
    'ocr_latency_total': 0.0,
}
```
No external dependencies needed — log as a single INFO line:
```
[STATS] uptime=42m | ocr_cycles=1680 | avg_ocr=1.24s | respawn=3 | incoming=7 | click_to=6
```
