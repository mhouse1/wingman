## Fix Before Phase 3

### 1. FSM bypass on J20 hotkey

**Source:** CR-008 H-4

Current code still writes `analyzer.state = GameState.GAME_BATTLE.name` directly on
the J20 hotkey path and then calls `on_enter_GAME_BATTLE()` manually. This is not
compatible with an FSM being the single source of truth.

**Why it matters before BT:** ADR 024 assumes `game_state` is authoritative for tree
selection. A controller-side state bypass creates exactly the kind of implicit edge
that will be hard to reason about once tactics are selected by the BT.

**Required outcome:** Replace the direct state write with a trigger-driven FSM path.

### 2. `_trigger()` lock scope

**Source:** CR-008 H-4b

`GameStateAnalyzer._trigger()` currently holds `_state_lock` while entry hooks can
call external side effects, including mission-cancel paths that join threads.

**Why it matters before BT:** Phase 3 increases the importance of responsive and
predictable state transitions. Long critical sections in the FSM layer are not
eliminated by adopting a BT.

**Required outcome:** Keep state mutation protected, but move expensive side effects
outside the lock.

### 3. FSM-level lifecycle tests

**Source:** CR-002 5.1/5.2 and CR-003-11

The old rationale for deferring some tests was that the boolean-flag surface was in
flight. ADR 025 is already implemented. The current missing coverage should now be
written against the FSM surface rather than the deleted flag model.

**Required outcome:** Add regression coverage for the unattended lifecycle and the
GAME_STARTING loop against the current `game_state` / `_trigger()` model.

### 4. Maneuver-key cancel regression test

**Source:** CR-003-12

The maneuver-key path remains active in `Controller` and still drives mission
cancellation / manual takeover behavior. This path should have a focused regression
test independent of unattended lifecycle coverage.

**Required outcome:** Add a regression test for maneuver-key behavior across at
least `GAME_BATTLE` and non-battle states.

## Fold Into Phase 3

### 1. Duplicate lobby-entry cancellation

Keep this as opportunistic cleanup. It is visible and unnecessary, but not a Phase 3
gate because the duplicate call is idempotent and has not shown correctness fallout.

### 2. Timeout ownership for `GAME_STARTING`

This should be revisited while Phase 3 decides where orchestration belongs, but the
current controller-owned timeout is functional and not worth a pre-BT detour.

### 3. Click-to polling state review

Re-evaluate once Phase 3 integration decides whether click-through remains outside
the BT or becomes part of a more explicit flow wrapper.

### 4. Observability counters from CR-002

`PerformanceTracker` already provides OCR timing and reaction-latency tracking, but
CR-002 also called out aggregate event counters (respawn, incoming, mission restart,
click-to) that remain partially uncovered. Treat this as carry-forward observability
work, not as stale debt.

## Carry As Investigation

### 1. INCOMING crop bleed

Keep as an investigation item, not a pre-Phase-3 fix. The system is currently
rejecting the observed stray OCR correctly, and crop movement without screenshot
evidence is higher risk than the current false-negative-free behavior.

### 2. Health ceiling ratchet tuning

Keep as a live-data calibration item. It becomes more important when Phase 3 starts
using health thresholds for tactics such as EVADE, but current evidence supports more
observation before tuning filter constants.
