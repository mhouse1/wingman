## Finding Details

### CR-014-1 — Stale-telemetry poll instantly releases a confirmed hold (High, CONFIRMED)

The `band is None and not descending_hard` branch has no `confirmed_hold`
awareness. Mid-hold, `legacy_deadline` (phase start + 5 s) expired tens of
seconds ago, so the first poll where both `pitch_band()` and
`pitch_angle_deg()` return None — speed stale >6 s with altitude fresh and
descending (the code's own comment documents 9 such samples in one session),
altitude stale, or a rate=None reseed after a gap — returns `no_telemetry`
immediately. An angle-confirmed dive (~160 m/s, under the 250 raw-confirm
bar) has no second confirming signal, so the key drops on a healthy descent,
the game auto-levels, and the overwritten exit_reason disarms the confirmed
decay re-entry. Contrast: a *frozen* sensor is granted 6 s of grace at line
1457; a stale-speed poll gets zero. Fix direction: a dedicated hold loop (or
`if confirmed_hold: return False` preserving `confirmed` in the stale branch)
with its own staleness tolerance.

### CR-014-2 — Stale reversal baseline fires nose-up during in-hold decay (High, CONFIRMED)

`rate_before_correction`, `corrections`, and `_eject_reached_target_dive`
survive re-confirmation within a phase. Decay #1 issues a nose-down correction
(baseline -60); the dive re-establishes and re-confirms; decay #2 much later
crosses -50: `over_rotated` sees corrections>0, target-reached (sticky),
descending, shallower-than-baseline → nose-up tap against an auto-level decay.
Reachable whenever `corrections` is 1–2 at the decay; auto-level monotonically
shallows the rate so the crossing is robust. This is the same misfire class
ADR 068 d6 fixed at phase scope, recreated across decay cycles inside one
phase. Fix direction: clear the correction baseline (and re-arm requirements)
on each re-confirmation — each decay cycle is a fresh rotation attempt.

### CR-014-3 — Correction budget ends confirmed holds mid-descent (Medium, CONFIRMED)

`corrections` only increments; `window_deadline` was last set pre-confirmation.
An eject that spent 3 corrections rotating hits its first in-hold decay sample
and exits `budget_exhausted` (overwriting `confirmed`) with the key released
mid-descent. Multi-decay holds burn the budget cumulatively (17 decay events
per 13-eject session observed). Downstream re-entries restart with a fresh
budget, so the cost is release/auto-level/re-enter churn rather than dive
loss. `test_decay_while_held_recovers_without_release` passes only because it
sets `max_corrections=99`; production is 3. Fix direction: reset or separately
budget in-hold recovery.

### CR-014-4 — Afterburner verification unreachable on the success path (Medium, CONFIRMED)

AFTERBURNER is pressed once at engagement; the only missed-press detection
(speed-trend check + bounded re-press) lives inside `if not cancelled:`. The
dominant path now ends the phase via respawn (`cancelled=True`), skipping the
watcher entirely — a missed afterburner press goes uncorrected for the whole
40–80 s descent. Bounded consequence (slower descent), but the check existed
precisely because missed injections are documented in this project's flight
data. Fix direction: verify afterburner engagement inside the hold loop.

### CR-014-5 — Single-sample over-rotation abort (Medium, CONFIRMED)

During a hold, `descended_since_press` and the 6 s held-time threshold are
permanently satisfied and `window_deadline` is expired, so one accepted
positive-rate sample (a single thousands-digit altitude OCR substitution
passes the plausibility gate at dive speeds and yields ~+333 m/s) releases the
hold as `over_rotation` — and the guard has no `sample_ts` dedup, so even a
re-poll of the same reading fires. Confirmation demanded 2 distinct samples;
abandonment takes 1. Fix direction: extend `confirm_consecutive`-style
distinct-sample debouncing to the guard during holds.

### CR-014-6 — Frozen-sensor hold-release branch is dead code (Low, CONFIRMED)

The branch requires a sample simultaneously fresh at snapshot (age ≤ 6.0 s)
and frozen at the check (age ≥ 6.0 s) — a race-width window against a 1.5 s
poll cadence. Real freezes exit via CR-014-1's path with the misleading
`no confident telemetry by legacy deadline` log and the wrong exit label. The
4×check_interval constant and `stale_after_s` are independently tunable, so
the exact-equality coincidence can silently become divergence in either
direction. Fix direction: fold the frozen-hold release into the stale branch,
expressed against `stale_after_s`.

### CR-014-7 through CR-014-13

Documentation, maintainability, and hygiene items as summarized in the table:
the contradictory no-release comment/test name (7); `exit_reason` twin-state
drift plus stale release-on-confirm comments in the watcher (8); the
two-roles-one-knob budget arithmetic, usually benign because respawn or
momentum finishes the descent (9); the guard-refusal-invisible re-entry,
bounded to 2 re-entries (10); validator accounting for non-respawn in-phase
cancellations, latent until validators meet live-session logs (11); test
helper inconsistency and the failure-path thread leak (12); and the redundant
evidence-flag reset sites (13).

## Assessment

The hold-through-descent direction is sound and its primary outcome is proven
in flight (13/13 autonomous ejects, all reaching −90°). The dominant defect
pattern — four of the six confirmed findings — is a single root cause:
machinery calibrated for a ~5-second rotation phase (legacy deadline,
correction budget, reversal baseline, over-rotation guard) now executes
throughout a 40–80 s hold without being re-scoped to it. The recommended
remediation is one structural change: give the confirmed hold its own small
loop (stop / budget / deduped over-rotation / stale-with-grace / decay exits),
which resolves CR-014-1, -3, -5, and -6 together and gives -2 a natural home
(per-decay-cycle baseline reset). CR-014-4 needs afterburner verification
moved inside the hold. Every confirmed failure mode is bounded — worst cases
are churn or a slower descent, not loss of the eject — so none block continued
flight testing, but CR-014-1 and -2 will visibly fire in real sessions under
conditions the logs show are routine.

## Resolution Summary (2026-08-09, same cycle)

All 13 findings resolved in one remediation pass (ADR 068 decision 7; file/line
references in the findings table describe the pre-fix code):

- **Structural (CR-014-1, -3, -5, -6):** the confirmed hold moved out of the
  establishment loop into a dedicated `_eject_hold_established_dive` loop with
  its own semantics — telemetry-loss release after `stale_after_s` without a
  fresh sample, exit_reason kept `confirmed` (regression test:
  `test_hold_telemetry_loss_releases_but_keeps_confirmed`); over-rotation
  release requires the same distinct-sample streak as confirmation
  (`test_hold_survives_one_spurious_climb_sample` /
  `test_hold_releases_on_sustained_climb`); a decay hands back to a fresh
  establishment cycle with a fresh correction budget
  (`test_decay_while_held_reestablishes_without_leaving_phase`, now at the
  production `max_corrections=3`); the dead frozen-sensor branch is gone.
- **CR-014-2:** decay cycles are separate rotation attempts — the reversal
  baseline, correction count, and evidence flags all reset at each
  establishment entry.
- **CR-014-4:** afterburner verification runs inside the hold loop with an
  eject-wide re-press budget shared with the post-release watcher
  (`test_afterburner_repressed_during_hold`).
- **CR-014-8:** `exit_reason` resets at phase entry; the `confirmed`-at-entry
  watcher regime is genuinely reachable again (stale/hold-timeout exits) and
  the stale release-on-confirm comments were rewritten.
- **CR-014-9:** held time at target is credited back to the rotation budget
  (`_eject_nose_hold_credit_s`); `total_nose_budget_s` returned to 40 s as a
  pure anti-loop bound; runaway holds bounded by `hold_max_s` (120 s) instead.
- **CR-014-10:** the watcher reads each re-entry's outcome back and suppresses
  further re-entries after an over-rotation refusal.
- **CR-014-11:** both validators exempt `match_ended` and `shutdown` in-phase
  cancellations.
- **CR-014-12:** shared `_stop_phase` / `_saw_nose_down_reissue` helpers, all
  hand-rolled thread blocks converted, and an autouse fixture stops any phase
  thread a failed test leaves behind.
- **CR-014-13:** the establishment loop is the single owner of per-attempt
  evidence scoping; the redundant `eject_and_dive` resets were removed.
