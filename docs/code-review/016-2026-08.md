## Notes

- This cycle also accumulated two new observations during the 2026-08-14 soak,

  overshoot (6–8 s under load, GIL/X starvation, benign) and XTest release
  latency under load (addressed by the scaled release-grace fix in
  `controller.py`).
- **CR-016-01 (new, Resolved): stuck-key leak from the test suite.** After a
  `make test` run the X server was left auto-repeating `i` into the focused
  window. Chain: tests neutralize `keyboard_module` via monkeypatch, which
  reverts at *test* teardown while unjoined mission daemon threads survive;
  the teardown's single `cancel_mission()` can be silently swallowed by
  mission entry's `_mission_cancel.clear()` (spawn-to-entry race); the
  surviving `mission_j20` thread then presses the REAL `i` (nose_up, 2 s
  hold), and pytest exiting mid-hold latches it server-side. Fixed with a
  session-end release-all-injectable-keys safety net in `conftest.py` plus
  drain-and-assert teardowns in `test_controller_no_keyboard.py` and
  `test_mission_cancel.py`. **Open follow-up:** the cancel-swallow race is a
  product bug too — `mission_j20`/`mission_loiter` entry clearing
  `_mission_cancel` erases any cancel that raced the thread spawn; moving the
  clear to the mission *starter* (before spawn) would close it for all
  callers.
