## Finding Details

### CR-012-1 — click_to outcome ordering race (Critical)

`_run_click_to_in_background()` in `analyzer.py` fires the FSM transition
`click_to_detected` directly from a background OCR thread. By the time
`on_fsm_transition` runs, the main loop has not yet called
`on_event("click_to_detected")`, so `_pending_outcome` is `None`.
The fallback at line 121 then classifies the mission as `"lobby_exit"` or
`"unknown"` instead of `"click_to"`.

**Resolution:** In the `outcome is None` branch, check
`trigger_name == "click_to_detected"` first and set outcome to `"click_to"`.
This uses the FSM trigger name (always reliable — passed directly from the
analyzer) rather than the pending-outcome hint (set by the main loop, which may
not have run yet).

### CR-012-2 — missing `import sys` in main.py (High)

`sys.platform` is referenced in the watchdog path at line 760 but `sys` is not
in the import block. The NameError is raised 10 minutes into every Linux
session when the watchdog timer fires.

**Resolution:** Add `import sys` to the top-level imports.

### CR-012-3 — PipeWire thread safety in grab_from_thread (High)

`grab_from_thread()` delegates to `get_frame()`, which reads and writes
`_game_offset`, `_miss_count`, `_detecting`, and `_detection_warned` without
any locking. The invited-popup detection path calls `grab_from_thread()` from a
daemon thread concurrently with the main loop calling `get_frame()` directly.

**Resolution:** Add `_last_frame` / `_last_frame_lock` to `__init__`. At each
successful return point in `get_frame()`, cache the frame under the lock.
`grab_from_thread()` returns the cached frame under the lock instead of calling
`get_frame()`. A slightly stale frame is acceptable for the INVITED popup use
case.

### CR-012-4 — stats_path missing from written JSON (Medium)

In `_write_json`, `data["stats_path"] = str(out_path)` is assigned **after**
`json.dumps(data, indent=2)`. The key is absent from the file on disk.

**Resolution:** Move the assignment before `json.dumps()`.

### CR-012-5 — inaccurate thread-safety docstring (Medium)

The class docstring states "on_event and on_fsm_transition are called from the
main loop thread only." CR-012-1 shows this is false: `on_fsm_transition` is
called from the background OCR thread via `click_to_detected`.

**Resolution:** Update docstring to accurately describe the threading model.

### CR-012-6 — dead constant `_MISSION_END_STATES` (Low)

`_MISSION_END_STATES` is defined at module level but never referenced anywhere
in the file. It was likely kept as documentation but misleads readers into
thinking it's used for outcome classification.

**Resolution:** Delete the constant.

### CR-012-7 — redundant `.get()` default masks novel outcomes (Low)

`counts` is pre-seeded with the four known outcomes (`click_to`,
`missiles_empty`, `lobby_exit`, `unknown`). The `counts.get(outcome, 0) + 1`
form silently handles keys not in the dict, masking any novel outcome that
leaks in. Using `counts[outcome] += 1` raises `KeyError` on an unknown outcome,
surfacing the problem immediately.

**Resolution:** Use `counts[outcome] += 1` directly.
